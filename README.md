# KazBeef — интерфейс

Веб-интерфейс мониторинга болезней КРС и МРС: обзор, карта очагов, список событий, аналитика и админка источников.
Самостоятельный проект: собирается, проверяется и разворачивается отдельно от бэкенда.

Стек: React 18, TypeScript, Vite, Mantine, TanStack Query, React Router, ECharts, Leaflet.

## Как интерфейс связан с бэкендом

Интерфейс обращается к бэкенду по путям `/api/...` и `/admin/...` **на своём же origin**.
Кто-то перед ним должен переправлять эти пути на бэкенд:

| Режим                | Кто проксирует              | Куда                                                     |
| -------------------- | --------------------------- | -------------------------------------------------------- |
| `npm run dev`        | dev-сервер Vite             | `DEV_BACKEND_URL` (по умолчанию `http://localhost:8080`) |
| Docker-образ         | nginx внутри образа         | `BACKEND_URL` (задаётся при запуске контейнера)          |
| Свой хостинг статики | ваш веб-сервер или балансер | см. `nginx/default.conf.template` как образец            |

Так сделано намеренно: вход работает через cookie сессии и CSRF-токен, и пока браузер видит один origin,
на бэкенде не нужны ни CORS, ни `SameSite=None`.

## Разработка

Нужен Node.js 22.12 или новее (версия записана в `.nvmrc`).

```bash
npm ci
npm run dev        # http://localhost:5173, бэкенд ожидается на http://localhost:8080
```

Бэкенд на другом адресе — скопируйте `.env.example` в `.env.local` и поменяйте `DEV_BACKEND_URL`.

## Сборка и развёртывание

### Docker (рекомендуется)

```bash
docker build -t kazbeef-frontend .
docker run -d -p 3000:80 -e BACKEND_URL=http://адрес-бэкенда:8080 kazbeef-frontend
```

Или `docker compose up -d --build`: интерфейс на `http://localhost:3000`, бэкенд ожидается на этой же машине,
порт 8080. Оба значения меняются переменными `FRONTEND_PORT` и `BACKEND_URL`.

Адрес бэкенда подставляется **при старте контейнера**: один образ годится для любого окружения.
Проверка живости: `GET /healthz`.

### Статика без Docker

```bash
npm ci && npm run build   # результат в dist/
```

Содержимое `dist/` можно положить на любой веб-сервер. От него требуется три вещи:

1. проксировать `/api/` и `/admin/` на бэкенд;
2. на неизвестные пути отдавать `index.html` (маршруты вроде `/map` и `/events` обрабатывает само приложение);
3. не кешировать `index.html`; файлы из `/assets/` можно кешировать навсегда — в их именах хэш содержимого.

Готовый пример — `nginx/default.conf.template`.

### Параметры сборки

Задаются переменными окружения перед `npm run build` (в Docker — через `--build-arg`):

| Переменная     | Зачем                                                                                                                                  |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `VITE_BASE`    | базовый путь, если приложение лежит не в корне домена, например `/kazbeef/`                                                            |
| `VITE_API_URL` | адрес бэкенда на **другом** origin. Обычно не нужен; потребует на бэкенде CORS с credentials и cookie сессии с `SameSite=None; Secure` |

## Устройство кода

```
src/
  api/         клиент (fetch, CSRF, ошибки), типы ответов бэкенда, ключи кеша и общие запросы
  auth/        вход и выход
  filters/     срез данных: модель (URL ↔ фильтры ↔ запрос к API), провайдер, панель фильтров
  components/  карточки, таблицы, графики, карта, состояния загрузки и ошибки
  layout/      каркас приложения: меню, шапка, маршруты
  pages/       страницы; грузятся по требованию
  lib/         чистые функции без React: форматирование, подготовка рядов для графика
  config.ts    всё, что зависит от окружения сборки
  theme.ts     палитры, уровни риска, подписи статусов
```

Несколько договорённостей, которые стоит знать до правок:

- **Фильтры живут в адресной строке.** Срез переживает перезагрузку, ссылкой можно поделиться.
  Ссылки меню несут строку запроса с собой — иначе переход между страницами сбрасывал бы фильтры.
- **Типы API — в `src/api/types.ts`.** Они сняты с контроллеров и SQL бэкенда. Поменялся API — правится этот файл,
  и компилятор показывает все места, которые нужно обновить.
- **Каждый запрос показывает три состояния:** загрузка, ошибка с кнопкой «Повторить», данные.
  `ChartCard` делает это сам, если передать ему `query`.
- **401 от любого запроса возвращает на экран входа** (см. `src/api/queryClient.ts`): истёкшая сессия
  не оставляет интерфейс в полурабочем состоянии.
- **У цвета три непересекающихся смысла.** Фирменный бордовый KazBeef (`#8c2628`) — оболочка: меню, кнопки, фокус.
  Синий — данные на графиках и карте. Красный, оранжевый, жёлтый и зелёный — только уровень риска.
  Токены лежат в `src/styles.css`, тема Mantine — в `src/mantineTheme.ts`.
- **Логотип и шрифты.** Логотипы в `public/` взяты с kazbeefshop.kz (`mark.svg` и `favicon.svg` собраны из того же
  контура). Шрифты Montserrat (заголовки, меню, числа) и Golos Text (текст, таблицы) лежат в сборке — запросов к
  сторонним серверам нет.
- **Тяжёлые библиотеки не попадают в первую загрузку.** Карта и графики подгружаются вместе со своими страницами;
  разбиение на файлы настроено в `vite.config.ts`.
